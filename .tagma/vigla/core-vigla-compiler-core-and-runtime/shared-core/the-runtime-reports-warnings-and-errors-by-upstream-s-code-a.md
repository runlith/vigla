Runtime diagnostics keep upstream's codes and messages — samples and tooling match on them: the hydration runner detects `hydration_mismatch` by the code in a `%c[svelte] <code>` line, and `error`/`runtime_error` samples look for the code in a thrown message. The `[svelte]` prefix and the `https://svelte.dev/e/<code>` line belong to Svelte's world, which the core may not name, so the core hands the reporter installed through `setReporter` a notice: code, message, the message's values and whether the core runs in `DEV`. The reporter decides how much to print, because upstream's policy is per diagnostic: outside `DEV` it prints only the link for client and shared diagnostics, while its server errors always carry their message. A reporter belongs to a front end. `setReporter(reporter, format)` registers it for the trees mounted, hydrated or rendered with that format. The registration is keyed by the format's `global` name, because a framework such as Kit hands the runtime a copy of the front end's format, not its object. A diagnostic uses the reporter of the nearest tree on the current owner chain; a native tree prints the core's form. A diagnostic raised under no owner — an event handler, API misuse at top level — uses the realm default that the unkeyed `setReporter` installs; trees and their unhandled failures are [[4ece65b4]]. The Svelte adapter installs its reporter both ways when `svelte/internal/client` or `svelte/internal/server` loads, which every compiled component imports first. A native tree in the same realm therefore prints the core's form, while a diagnostic raised outside every tree prints in Svelte's form once the adapter has loaded. Until something installs one, the core warns `code: message` and throws an error whose message is the code and message on two lines, or only the code outside `DEV`. Where upstream's code or wording names Svelte — `<svelte:boundary>`, `<svelte:element>`, a store — the core reports its own code and words, passing the message's parameters as values. The adapter's reporter projects the code and message to upstream's from those values, never by editing the core's text. The stacks `$inspect(...)` prints follow that boundary too, through `formatFrame`: the adapter projects its public collection names without renaming the shared constructors, and drops the frames of its own entries, which the core does not know. `$inspect.trace` logs its captured errors without that hook. Errors returned by the diagnostic factory retain core identity independently of the reporter's presentation, so hydration can leave a framework failure fatal without parsing the adapter's message or wrapping its error.
