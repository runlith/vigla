**Svelte** (`packages/svelte/tests`, vitest; jsdom for the runtime suites, Playwright Chromium for `runtime-browser`). Samples per suite: runtime-legacy 1209, runtime-runes 1098, validator 337, css 184, compiler-errors 150, server-side-rendering 132, hydration 86, parser-legacy 84, migrate 78, print 51, runtime-browser 39 plus 36 custom-element samples and `test-ssr.ts`, snapshot 34, sourcemaps 29, parser-modern 28, preprocess 19, runtime-xhtml 13, runtime-production 6. `motion`, `signals` (55 tests on the reactive core) and `store` (33 tests) are single test files; `types` holds type tests run by `tsc`. Outside `tests`: 12 unit test files under `src/**/*.test.ts` (SvelteMap, SvelteSet, SvelteDate, SvelteURL and SvelteURLSearchParams, `proxy`, `clone`, renderer, `hydratable`, crypto, error handling, utils) and `tests/css-parse.test.ts` (public `parseCss`).

**Runtime harness.** A runtime sample is a directory with `_config.js` and `main.svelte`. The shared runner (`runtime-legacy/shared.ts`) compiles each sample for client and server and runs the variants `dom`, `hydrate`, `ssr` and `async-ssr`, narrowed per sample by `mode`, `skip_mode`, `skip_async` and `skip_no_async`; a variant is either skipped visibly or absent (`'no-test'`). runtime-runes, runtime-production and runtime-xhtml call it with runes on; runtime-production also mocks `esm-env` to `DEV: false`. Async mode is on by default: `async_mode = process.env.SVELTE_NO_ASYNC !== 'true'` in `tests/helpers.js`. In runtime-runes, 287 sample names start with `async-`, 23 configs set `skip_no_async`, 2 set `skip_async` (`const-tag-boundary-deprecated-usage`, `untrack-own-deriveds`).

**What the runner does through internals.** It clears state between samples with `clear` (`src/internal/client/reactivity/batch.js`), `hydrating` (`src/internal/client/dom/hydration.js`) and `ssr_context` (`src/internal/server/context.js`); builds reactive props with `proxy` from `svelte/internal/client`; resets `globalThis.__svelte.uid = 1`, the `$props.id()` counter; defaults `accessors: true`; hydrates through `createClassComponent` from `svelte/legacy`. `tests/animation-helpers.js` fakes timing by overriding `raf.tick`, `raf.now` and `raf.tasks` from `svelte/internal/client` and importing `queue_micro_task` from `src`. Sample configs import upstream paths: 25 across the suites import `../../../../src/index-client`, 27 import `../../../helpers.js` or the animation helpers. Some samples assert internal formats: `hmr-dynamic-component` imports the `HMR` symbol, 5 `svelte-meta*` samples assert `__svelte_meta.loc`, 3 `csp-*` SSR samples pin the `(window.__svelte ??= {}).h` script text, the props-id samples pin id text.

**HTML comparison.** `tests/html_equal.js` strips comments unless `preserveComments` is set; its `withoutNormalizeHtml` path keeps them when `preserveComments` is undefined. 3 samples set `preserveComments`; 7 hydration samples feed hand-written upstream markers (`<!--[-->`, `<!--]-->`) through `_override.html`.

**Legacy syntax in runes mode.** Upstream rejects in runes mode: `export let`, `$$props`, `$$restProps`, `$:`, importing `beforeUpdate` or `afterUpdate`. It only warns in runes mode for `on:` on elements, `<slot>` outside custom elements, `<svelte:component>`, `<svelte:self>`, `context="module"`, the `accessors` and `immutable` options — so runes samples pass with them: in runtime-runes, 110 samples use an `on:` directive on an element, 10 `<slot`, 9 `<svelte:component`, 5 have `runes={false}` children, 2 import `svelte/legacy`, 1 `createEventDispatcher`; 39 use stores. JSDoc marks `createEventDispatcher`, `beforeUpdate`, `afterUpdate`, `spring`, `tweened` and the types `SvelteComponent`, `ComponentType`, `ComponentEvents`, `ComponentConstructorOptions` deprecated. Outside runtime-runes, samples whose `.svelte` files use a rune: hydration 21 of 86, server-side-rendering 21 of 132, css 3 of 184, validator 31, compiler-errors 31, snapshot 14, runtime-browser 15, runtime-xhtml 7, runtime-production 4, sourcemaps 1.

**What upstream tooling reads.** `svelte-check` 4.7.7 resolves `svelte/package.json`, takes its `version` (Svelte 5 handling when the major is above 4) and `require`s `<package dir>/compiler`, which upstream ships as a UMD bundle with `compiler/package.json` `{"type": "commonjs"}`. Its svelte2tsx calls `parse(code, { loose })` without `modern: true` and reads `parsed.html` — the legacy-format AST the `parser-legacy` suite pins. Its shims reference `SvelteComponent`, `ComponentConstructorOptions` and `ComponentType`. vite-plugin-svelte reads `VERSION` (async from 5.36.0) and builds its import lists from the package's `exports` and `dependencies`.

**SvelteKit** (`packages/kit`): 75 unit spec files beside the source, run by `vitest.kit.config.js`; integration apps in `test/apps` (async, basics, dev-only, embed, hash-based-routing, no-csr, no-ssr, options, options-2, options-3, prerendered-app-error-pages, writes; `read-file-test` is a fixture of basics), `test/build-errors` (6 spec files), `test/prerendering` (3 apps) and `test/types`. 23 files match Kit's Playwright `testMatch`; each app runs in dev and build except `dev-only` (dev only) and `no-csr` and `options-3` (build only); Playwright projects split by mode with and without JS; extra variant scripts run route resolution on the server, cross-platform and `paths-*`. Only the `async` and `options-2` apps compile with async on; `basics` follows `SVELTE_ASYNC` and also enables `tracing.server`; one basics test is skipped under async. The `async` app holds 71 of the 72 `.remote.*` files. Playwright uses `channel: 'chrome'`. 191 of the 766 `.svelte` files in the apps contain `$app/stores`, `svelte/store`, `export let` or `<slot` (text matches); in basics, of 553 files, 129 contain `export let`, 45 `<slot`, 5 `$:`, 5 `on:`, 2 `<svelte:component`. Kit typechecks with `@typescript/native`. Adapters carry their own tests (`adapter-node/test/apps`, `adapter-static/test/apps`, `adapter-auto/test/adapters.spec.js`); `adapter-auto` installs the Vercel, Cloudflare and Netlify adapters.

**vite-plugin-svelte**: unit specs in `packages/vite-plugin-svelte/__tests__` (compile, id, preprocess, sourcemaps, svelte-version) and 26 test projects in `packages/e2e-tests` (24 without the inspector), run in `test:serve`, `test:build` and `test:build:watch` modes.

**Benchmarks**: `benchmarking/benchmarks` holds `compiler`, `reactivity` and `ssr` suites. The compiler benchmark times the internal parser (`src/compiler/phases/1-parse/index.js`); the 13 reactivity benchmarks and `benchmarking/run.js` drive `svelte/internal/client`; only the SSR wrapper benchmark uses public `compile` and `render`.

**Not established**: which samples upstream's own runner passes with runes forced on every compiling suite.
