## Findings (2026-11-03, wrap-up)

Method: scratch apps, upstream Kit 3.1.0 / Svelte 5.57.3 / vite-plugin-svelte 7.3.1 vs Vigla, dev mode, async forced, one Chromium. Scratch apps and driver: `/Users/teunlao/.tagma-dev/scratch/01a1a145-3dc5-7721-affb-cff479df7252/forms`.

- Not reproduced on upstream or Vigla (non-failing fork-base runs; candidate drops): #9478 (1,760,003 of 1,760,003 characters reach the action), #15908 (`fields.intent.value()` and `fields.value()` hold the submitter value in the enhance callback), #16270 ("20.5", Backspace, "7" yields 20.7; the browser reports "" only for the transient "20."), #15270 (a browser-typed `minlength` blocks the POST: 0 requests), #15104 (no stale issue after Enter submit under forced async).
- Red on upstream, green on Vigla: #13825 (`page.form` becomes null after `invalidateAll` on upstream; the prop and `page.form` both keep the result on Vigla). Sample `own/kit/forms` test `page.form survives invalidateAll like the form prop`.
- Landed in b4a351be5e (sample `own/kit/forms`, red on upstream with their own assertion, green on Vigla on attempt 0): #11123 (`client/forms.ts` submits the reassigned `formData`), #13825, #14802 and #15815 (a remote form's input, issues and result clear after its last element leaves the page; documented as ephemeral), #16359 (`fields.value()` is completed from the submitted FormData, with `[]` for array groups, when an enhance callback runs; explanation 77fcb6c9).
- Fix idea not landed, unproved: #15547 (concurrent `validate` calls return the trailing call's promise: `validate` kept a generation counter and a superseded call returned at once, before the trailing call set the issues), #15230 and #17131 (a select's `value` attribute is omitted while the field is unset, so a spread rerun no longer clears untouched selects with `selectedIndex = -1`; the cause is the spread update in `runtime/dom/attributes.ts` re-applying an undefined single-select value, which upstream also does for array paths), #16093 (selects declared with a default carry `defaultValue`, so a form reset returns to it; the select runtime already honours it). The sample pages for these four did not render on either target (an `$props.id()` placement or a page error not diagnosed), so the run proved nothing; the code and tests were withdrawn.
- Not investigated, open: #14729 (reporter's StackBlitz unreadable; a reactive default survives two identical submits on both targets), #14990 (3.1.0 warns `remote_form_issues_ignored` in dev; not verified in a run), #10464 (CSRF runs only in builds; Vigla's enhance already reports `type: 'error'`, status 403, upstream hands back the bare `{message}`; needs a build run), #14698 (circular import between a component's module script and its remote file; upstream silently takes an undefined validator and Vigla throws `remote_invalid_validator`; probably not fixable in Kit), #16444 (Firefox only), #16818 (WebContainer only; cannot reproduce on Node).
